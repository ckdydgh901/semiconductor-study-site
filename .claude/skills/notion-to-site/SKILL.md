# 노션 → 공부 사이트 변환

이 사이트(`topics/<id>/index.html`)는 노션 원본의 웹 기록본이다. 프로젝트 루트의 `CLAUDE.md`가 최상위 규칙이고, 이 스킬은 그 규칙을 따르는 **실행 절차**다. 규칙이 충돌하면 CLAUDE.md와 사용자의 최신 말이 우선한다.

## 0. 고정 규칙 (매번 지킬 것 — 사용자 지시)
1. **전부 옮긴다.** 일부 구간 제외·요약 금지. 오래된 PDF(`exports/`)는 기준이 아니다.
2. **원문 그대로.** 말투·감상·오타 유지. 오류로 보이는 부분은 고치지 말고 사용자에게 알린다(예: `330-340mm`).
3. **개인정보·개인 메모·취업 얘기도 가리지 않고, 있다고 묻지도 않는다.** 개인 저장용 사이트다.
4. **노션 댓글을 `[댓글]` 박스로 함께 넣는다.** (`notion-get-comments`, `include_resolved: true`; 위치는 `text-context`/`discussion-urls`로)
5. **노션 쓰기는 사용자가 요청했을 때만.** (예외 없음. 첨자·단위 수정은 사용자가 승인했을 때 사이트와 노션을 함께 수정 → `notation-fix` 스킬)
6. **첨자·단위 표기는 새 주제에서는 먼저 묻는다.** 반영 전에 후보를 "이런 것들을 바꿔드릴까요?" 목록 한 번으로 묻고, 승인 뒤에 바꾼다. 묻기 전에는 원문 그대로 둔다. 이미 올라간 페이지에서 발견한 개선점은 묻지 않고 고친다(→ `notation-fix`).
7. **질문 노트(`[질문 노트]`)는 사용자가 "기록해줘"라고 할 때만** 쓴다(→ `site-qa-note`). 영상(유튜브) 보완도 요청이 있을 때만.
8. **질문과 답은 한 세트로 `[질문 노트]` 박스 하나에**(CLAUDE.md 참조): 질문 뒤 이미지가 끼면 이미지·그 뒤 답까지 같은 박스에 넣는다. 사용자 노트 필기 박스에 `Q.`/`A.`가 남아 있지 않은지 변환 후 확인한다.
8. **표기 형식 유지(최우선)**: 필기 = 회색 `.note` + `[사용자 노트 필기]`, 질문/답 = `.note.qa` + `[질문 노트]`, 댓글 = `.note.cmt` + `[댓글]`(`<p class="cmt-ctx">대상: “…”</p>`), 이미지 캡션 끝에 `(출처: 사용자 노션 캡처)`. 구조 순서: 섹션 제목 → 본문 → 이미지 → 노트 필기 → 질문 노트. 모든 `h2`/`h3`에 고유 `id`, `<img>`에 `width`/`height`.
9. 색은 CSS 변수만, 외부 리소스는 Google Fonts(Noto Sans KR)만, `file://`에서 동작해야 하므로 `fetch`/ES module 금지.

## 1. 영역·id 정하기
- `study` 반도체 공부 / `news` 반도체 시사 / `thein` 더인 교육. 사용자 말 우선, DB `종류=교육`·제목 "더인 교육 N일차" → `thein`, 기사·시사 → `news`, 나머지 → `study`. 애매하면 한 번만 묻는다.
- id: 영문 소문자·숫자·하이픈(`thein-day6`). 내용이 제목뿐인 페이지(예: 3일차)는 넣지 않고 사용자에게 알린다.

## 2. 절차 (변환 스크립트 사용)
스크립트는 `scripts/`에 있다(경로는 파일 위치 기준 상대경로라 그대로 실행 가능). 작업용 폴더는 세션 scratchpad를 쓴다(`<W>`).

1. **노션 읽기** — `ToolSearch`로 `notion-fetch`, `notion-get-file-download-urls`, `notion-get-comments`를 불러온다. `notion-fetch`(include_file_urls: true, include_discussions: true)로 페이지를 읽는다. 응답이 파일로 저장되면 그 파일(JSON: `text`, `references`)을 쓴다. **이미지 URL은 5분 만에 만료**되니 읽은 직후 같은 턴에 받는다.
2. **이미지 병렬 다운로드** — `python scripts/dl_all.py <fetch결과.json> <tag> <W>` → `<W>/<tag>_raw.txt`, `<W>/<tag>/raw01.bin…`. (단일 순차 다운로드는 큰 사진에서 멈춘다.) 응답이 화면으로 그대로 오는 작은 페이지는 공통 토큰만 옮겨 이미지별 id·서명만 바꿔 병렬로 받는다.
3. **이미지 변환** — `python scripts/make_images.py <W> <tag> <id>` → `topics/<id>/images/figNN.(jpg|png)` + `<W>/<tag>_meta.json`.
4. **댓글** — `notion-get-comments`(page_id, `include_resolved: true`)로 읽고, 앵커(`discussion-urls`의 끝 12자리)별로 댓글 텍스트를 딕셔너리로 만든다(`build_example.py`의 `cm4` 참고). 원문 그대로, 줄바꿈은 `<br>`.
5. **빌드 스크립트 작성** — `scripts/build_example.py`를 복사해 `H2_*/H3_*`(제목 승격), `INSERT_*`(합성 `h2` 삽입), 이미지 캡션 딕셔너리(`cap*`: 슬라이드·판서 설명, 끝에 출처 자동)를 채우고 실행. 노션 원문의 제목은 `RENAME`으로 바꾸지 말고 그대로 둔다.
6. **누락 검사** — `python scripts/check_complete.py <W> <tag>:<id>`. `missing 0`이어야 한다. (표기 수정을 노션에도 반영한 뒤에는 `<tag>_raw.txt`가 옛 표기라 표기 줄만 "누락"으로 뜬다 — 다시 fetch한 raw로 검사하면 사라진다.)
7. **첨자·단위 후보 추출 → 사용자에게 질문** — `notation-fix` 스킬의 후보 스캔을 돌려 목록으로 **한 번에** 묻는다. 승인되면 사이트와 노션을 함께 고친다.
8. **`topics.js` 등록** — `id, area, title, short, category, summary, tags, updated(오늘 날짜), notion(원본 링크)`. 기존 주제를 고친 경우에도 `updated`만 갱신. `node -e`로 파싱 확인.
9. **CLAUDE.md "현재 주제"에 한 줄 추가**(이미지·댓글 수 포함).
10. **브라우저 검증** — 로컬 서버(`python -m http.server`, 프로젝트 폴더에서)로 열어 ① 상단/하위 탭 ② 사이드바 목차·스크롤 추적 ③ 이미지 전부 로드(깨진 것 0) ④ 375px 가로 스크롤 없음 ⑤ 다크모드 ⑥ `[댓글]` 박스 수가 노션 댓글 수와 같은지. 끝나면 서버를 반드시 종료한다(Windows: PowerShell `Stop-Process`; Git Bash `pkill`로는 안 죽는다. 서버가 폴더를 잡고 있으면 이름 변경이 막힌다).

## 3. 변환기가 처리하는 노션 문법
`inline()`이 마크다운 이스케이프(`\~ \* \^` 등) 해제, `<br />`, `<span discussion-urls>`, 색 span을 처리한다. `parse()`는 이미지·`---`·`####`·`<p>`·불릿·`<columns>`·`<callout>`·`<quote>`를 읽고, `Builder`가 제목 승격, `Q.` 줄 기반 질문 노트 묶기, 댓글 박스 삽입을 한다. `<table>`은 `.table-wrap` 표로, 별도 줄 `$$…$$` 수식은 `.note p.eq`(분수·첨자·∝·exp 지원)로 옮긴다(2026-11-14 추가). 삽입 규칙의 키에 `@IMG<번호>`를 쓰면 그 이미지 앞에 제목을 넣을 수 있다. 굵은 글씨 여러 개로 쪼개진 제목(`<b>(1) </b><b>$k_s$</b>…`)은 `</b><b>`를 지워 하나로 합친 뒤 비교한다. 새 문법이 나오면 `notion2site.py`를 고치고 누락 검사로 확인한다.

## 4. 끝낼 때 사용자에게 알릴 것
섹션 수·이미지 수·댓글 수, 누락 검사 결과, 건너뛴 페이지와 이유, 원문에서 오류로 보이지만 그대로 둔 부분, 승인을 기다리는 첨자·단위 목록.
